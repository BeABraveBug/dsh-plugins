# 侧边对话（Side Chat）

DeepSeek Harness 的侧边会话插件。右侧栏面板、多侧聊、草稿持久化、首次发送创建独立会话、关闭/恢复/归档、失败提示、主会话选文引用与自动背景已可用。

## 状态

行为要求与目标结构见 [Spec](docs/spec.md) 与 [Architecture](docs/architecture.md)（V1.2，产品要求不代表已全部实现）。已实现并验证：右侧栏「侧边对话」标签、新建/切换/关闭并保留/恢复/归档侧聊、草稿与状态持久化、刷新后恢复、首次发送创建真实 Session、显示已提交消息与本轮失败原因、主会话选文引用、自动主会话背景。尚未实现：删除底层会话；助手回复因验证环境缺少模型凭据未验证。

背景与归档已实现：背景预算 8000 字符，首轮无引用时自动附加，失败/未完成补读会保留草稿并报错。管理上默认归档保留记录；归档请求立即禁止新提交，等待当前已接受任务结束后进入只读；统一归档入口可跨主会话查阅；永久删除尚未提供。V1 允许回复完成后显示全文，不要求逐字流式显示。

本轮已接入默认归档、等待任务终态和统一归档入口；真实运行中任务归档、跨主会话查阅与宿主端到端仍未验证。

## 安装

需要 Node.js `^22.19.0 || >=24.0.0`，以及 DSH `>=0.2.1-rc.2 <0.3.0`。包名为 `dsh-side-chat`。在本仓库根目录执行：

```sh
pnpm install
pnpm --filter dsh-side-chat build
dsh plugin --profile web add "$PWD/plugins/side-chat"
```

将 `web` 替换为实际使用的 profile。安装后可在右侧栏指南中打开「侧边对话」面板。升级、卸载及其他安装方式见[安装与升级插件](../../docs/installation.md)。

## 使用

- 点击 `+` 新建草稿，输入问题后发送；首次发送才创建真实 DSH 会话，优先加入父会话所属工作区并使用该工作区目录；无法确定工作区时使用父会话工作目录。
- 顶部标题打开侧聊列表，分为「打开的侧聊」与「已保留」；`···` 菜单提供关闭并保留、恢复与归档。归档是默认的移出方式，保留记录与真实历史；当前版本没有永久删除入口。
- 会话头部的「侧边对话」按钮可打开或展开右栏面板；右栏指南中也有同一入口。
- 在主会话中选中一条用户或助手消息（含代码块）内的文字，点击浮出的「侧聊提问」把选区加入当前活动的侧聊；没有打开侧聊时会新建草稿。引用不会自动发送。
- 引用以卡片显示在输入框上方，可单独移除或一键清空；每个侧聊最多 5 条、单条最多 8000 字符。卡片截断显示，悬停可看到完整文本。发送时引用作为普通用户消息中的外部材料放在问题之前，发送成功后清空待发送引用并保留来源快照。
- 侧聊会话等待工具授权时，面板显示工具名、同 `callId` 的工具调用参数与本地化原因，可直接「允许一次」或「拒绝」；若当前窗口找不到该调用，批准按钮禁用并提示先加载更早消息或使用宿主原生审批入口。其他类型的宿主交互目前只显示等待提示。
- 侧聊记录加载完成前输入框与发送按钮不可用，避免用局部状态覆盖已有记录。
- 长侧聊可按「加载更早消息」继续读取更早的历史；助手最终回复在完成后显示，未接入逐字流式呈现。
- 首轮发送有主动引用时只用引用，不附加背景；没有引用时自动读取主会话已完成的用户/助手正文，按 8000 字符预算从最近向前取材，窗口不足时补读更早历史，遇到放不下的完整消息即停止（不为凑满预算继续拉取），超长单条标记为节选。背景正文发送给模型但不在侧聊消息区重复显示（按本插件写入的精确包裹剥离，不会改写问题里的同名文字）；后续追问依赖侧聊自身历史，不自动补入。背景读取失败、补读失败或未读完时不会发送，草稿与引用保留。
- 顶部下拉有「归档中」与「已归档（只读）」分区：`···` 菜单可归档；若当前任务仍在运行，先进入「归档中」并拒绝新提交，任务结束后转为只读。顶部 `▤` 打开统一归档入口，可跨主会话查看归档历史，不依赖原 Parent 存在；「归档中」的侧聊也会出现在该视图。Parent 出现 removed 状态时仅提示无法确认是否删除并保留侧聊，不自动归档。
- 侧聊标题、草稿、引用、上下文快照、活动项与真实会话映射保存在运行数据目录，刷新页面后恢复；加载期间新建的侧聊会与已存记录合并。
- 发送结果未知时会保留草稿并阻止重复提交；确认会话中还没有这条消息后，可点「确认未提交并重试」再发送。

## 兼容性

`package.json` 声明 Node `^22.19.0 || >=24.0.0`、DSH `>=0.2.1-rc.2 <0.3.0`，浏览器产物面向 Chromium 等支持 ES2022 的环境。右侧栏入口、会话头部入口、侧聊生命周期、持久化恢复、首次发送创建会话、跨父会话隔离、失败重试不重复创建会话与真实用户消息上的选文引用已在 DSH `0.2.1-rc.5` 的无凭据隔离 profile 中验证；助手回复、并行执行与模型/权限隔离尚未验证。

## 数据与隐私

侧聊的标题、草稿、待发送引用、活动项与真实会话映射保存在 `$DSH_HOME/side-chat/state.json`（未设置 `DSH_HOME` 时为 `~/.dsh/side-chat/state.json`）；对应的聊天记录由 DSH 作为普通会话保存，插件不复制消息。引用文本来自主会话，可能包含敏感内容，会随该文件写入磁盘。损坏的记录不会被自动覆盖，保存失败会在面板中提示。不支持多个 DSH 进程同时写同一数据目录。

主动发送会把输入交给所选的 DSH 模型服务，凭据由 DSH 管理，不经过插件。

### 当前会话管理方式

点击新建只保存插件草稿；首次发送才创建独立的普通 DSH 会话，并保存其 ID。主会话与侧聊在宿主侧是独立会话，关联关系由插件维护；加入同一工作区不表示继承主会话消息。关闭并保留只改变插件列表分类，不调用宿主归档；恢复继续使用原会话。归档保留插件记录、草稿、引用、背景快照与真实会话映射，统一归档入口按原映射读取历史，不创建新会话。当前没有永久删除入口；删除真实 DSH 历史需要宿主能力。可靠确认主会话删除后自动归档仍未完成，Parent removed 只提示保留。

在本机核对的 DSH `0.2.1-rc.5` 默认 JSONL 后端中，真实消息保存在 `$DSH_HOME/sessions/<工作目录编码>/<会话ID>/session.v4.jsonl.zstd`；未设置 `DSH_HOME` 时根目录为 `~/.dsh`。宿主可覆盖存储配置，具体布局随版本变化。工作目录是工具操作目录，不是聊天日志的保存位置。

## 已知限制

- 只有用户消息会被展示；助手回复需要可用的模型凭据，本仓库的验证环境没有验证这一路径。
- 归档不删除底层 DSH 会话，也不主动停止任务；归档请求后拒绝新提交，等待当前已接受任务结束。真实运行中任务归档流程仍需端到端验证。
- 侧聊元数据按父会话保存；统一归档入口会跨父会话读取归档记录。永久删除入口尚未提供。
- 旧版本创建过的侧聊会话可能仍留在侧栏「未分组」中；该分组是宿主的未归属会话桶，不是可删除的工作区，逐个归档这些会话后才会消失。新会话会加入父会话所在工作区。
- 多标签页同时编辑同一父会话的侧聊未验证；写入冲突没有检测。
- 选文引用只支持主会话中单条消息内的选择；跨消息、主输入框、工具输出与侧聊之间互相引用不在当前范围。助手消息节点键依赖宿主 `assistant-step` 命名，升级时复核。
- 选文浮层已按宿主实际节点键支持用户消息、助手消息与代码块；原生拖选与浮层边缘位置仍未实测。
- 背景是本地正文摘录，不做模型提炼；上限 8000 字符，可能包含与当前问题无关的内容，超长单条只保留节选。
- 结果未知时的对账依赖会话事件里是否出现本轮 `requestId`；宿主是否提供请求级幂等未验证。发送前会先保存提交身份，传输层错误按未知结果处理。
- 侧聊内可回答工具授权；展示内容依赖宿主 approval 域与 `tool/call` 事件形状，批准前要求能核验同 `callId` 的调用参数，参数可展开全文或复制。其他交互类型（例如提问、计划确认）仍只在主会话处理，升级 DSH 时需要复核。
- 未接入逐字流式输出，助手回复在完成后一次性出现。
- 关联会话失效时显示提示；归档记录仍保留，永久删除底层会话未实现。
- 自动归档未启用：removed 不足以证明持久化会话删除，目前只提示并保留侧聊。归档不调用宿主 `archiveSession`，普通会话列表可能仍显示该会话。
- 永久删除尚未实现：需要宿主能力与独立确认；当前没有可移除插件记录或底层历史的入口。
- V1 侧聊历史全量发送，不做固定字符/条数截断；长对话超过模型上下文时会明确报错并保留输入。自动压缩与主动压缩是后续功能，当前未实现。
- 归档等待期间若上一条提交结果未知，会按提交 `requestId` 在会话历史中只读对账（同文不同请求不会误判）；找到记录时按正常成功结算引用、草稿与首轮状态后继续归档；找不到时由你确认「未提交并归档」，不会自动重试发送。等待面板提供「按历史对账」与「确认未提交并归档」；确认动作会重新恢复会话、核对任务状态与 `requestId`，并再次查历史：命中则按成功结算，只有确实没有证据时才清收据归档。
- 验证环境的隔离 profile 没有模型凭据，真实模型对背景的使用与助手回复均未在真实会话中验证。
