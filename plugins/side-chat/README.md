# 侧边对话（Side Chat）

DSH 主会话旁的独立文字讨论区。每个侧聊由插件自己保存会话与消息，只借用 DSH 的默认模型和凭据，不再创建 DSH 原生会话。

## 状态

行为要求见 [Spec](docs/spec.md)，数据与模型接入边界见 [Architecture](docs/architecture.md)（V1.2，独立会话重写进行中）。

已实现：右侧栏面板、按主会话分组的新建/切换/关闭/恢复/归档、草稿与引用、SQLite 独立消息历史、DSH 默认模型文字问答、每侧聊模型覆盖、首轮主会话背景、统一只读归档、永久删除插件数据。

尚待验证/完成：真实模型下完整发送与重载、运行中归档、旧版 DSH 侧聊保留、跨父会话归档、断网/超时；自动压缩与主动压缩为后续功能。

## 安装

需要 Node.js `^22.19.0 || >=24.0.0`，以及 DSH `>=0.2.1-rc.2 <0.3.0`。在准备安装的那份检出根目录执行下列命令。测试开发分支时，使用原项目下的 `.worktree/side-chat/`。

```sh
pnpm install
pnpm --filter dsh-side-chat build
dsh plugin --profile web add "$PWD/plugins/side-chat"
```

将 `web` 替换为实际使用的 profile。安装后可从右侧栏指南或会话头部按钮打开。升级、切换检出和验证安装见原项目根目录的 `docs/installation.md`。

## 使用

- 点击 `+` 新建侧聊；输入问题后发送。侧聊不会出现在 DSH 会话列表，也不创建 DSH 会话。
- 顶部标题打开侧聊列表；`···` 提供关闭并保留、归档；`▤` 打开统一归档。
- 默认使用 DSH 当前默认模型；每个侧聊可在输入框上方切换到指定模型，只影响该侧聊。
- 在主会话中选中文字，点击「侧聊提问」把选区加入当前侧聊。引用发送成功后保留来源快照。
- 首轮没有引用时自动附加主会话背景（8000 字符预算，冻结快照，正文不在侧聊消息区重复显示）；首轮有引用时不附加。后续轮次不自动补入。
- 全量发送侧聊历史；不做固定条数/字符截断。超过模型上下文时明确报错并保留输入。
- 归档请求立即禁止新提交；正在生成时先进入「归档中」，完成后转为只读。统一归档可跨主会话查阅。
- 永久删除只删除插件保存的侧聊、消息与引用，必须单独确认；不会删除旧版 DSH 会话。

## 数据与隐私

侧聊、消息、引用、背景快照和模型覆盖保存在 `$DSH_HOME/side-chat/sessions.sqlite`（未设置 `DSH_HOME` 时为 `~/.dsh/side-chat/sessions.sqlite`）。旧版 `state.json` 在升级启动时清理，不再读取。

旧版创建的 DSH 侧聊仍是普通 DSH 会话，保留在原工作区，由 DSH 管理；插件不导入、不列出、不删除。

发送会把侧聊历史、引用与背景交给所选的 DSH 模型服务；凭据由 DSH 管理。V1 不调用工作区工具，也没有工具授权。

## 兼容性

`package.json` 声明 Node `^22.19.0 || >=24.0.0`、DSH `>=0.2.1-rc.2 <0.3.0`。SQLite 使用 Node 内置 `node:sqlite`（实验特性），发布环境需确认 Node 版本。

## 已知限制

- 真实模型发送、并行、长历史截断/超上下文、真实断网与重试尚未端到端验证。
- 自动压缩与主动压缩不在 V1；长对话可能因模型上下文不足而失败。
- 附件、工作区文件访问与工具执行不在 V1。
- 主会话删除后的自动归档仍缺可靠删除信号，当前只提示并保留侧聊。
- 多标签页同时编辑同一侧聊未验证；SQLite 写入没有跨进程冲突检测。
- 选文仅支持主会话单条消息内；节点键依赖宿主 `assistant-step` 命名，升级时复核。
- 未接入逐字流式输出，回复完成后一次性显示。

## 开发命令

在 `.worktree/side-chat/` 的根目录运行。

```sh
pnpm --filter dsh-side-chat typecheck
pnpm --filter dsh-side-chat test
pnpm --filter dsh-side-chat build
pnpm --filter dsh-side-chat check
```

`lib/` 是构建产物，由 `.gitignore` 排除；安装或更新源码后先构建。
